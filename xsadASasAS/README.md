# ТАУ — демо-магазин одежды

Вымышленный бренд для показа заказчику. Заказы не оплачиваются и не отправляются.

## Что есть
- Витрина: главная, каталог (поиск, фильтры, сортировка), товар, корзина, тестовое оформление, информационные страницы.
- Админ-панель `admin.html` (вход владельца через Supabase): товары, фото, размеры и остатки, тестовые заказы, выключатель демо-заказов.
- Без подключённой базы (`js/config.js` пуст) сайт работает в демо-режиме на встроенных товарах.
- Серверная функция `netlify/functions/notify-order.js` отправляет владельцу тестовый отчёт в личный Telegram.

## Файлы базы (Supabase → SQL Editor, по порядку)
1. `supabase/migrations/001_init.sql` — таблицы, правила RLS, тестовый заказ, хранилище фото
2. `supabase/migrations/002_demo_seed.sql` — 8 вымышленных товаров
3. `supabase/migrations/003_notified_at.sql` — отметка «отчёт отправлен»

## Публичные значения в js/config.js
`SUPABASE_URL` и `SUPABASE_ANON_KEY` (публичный ключ). Защиту данных обеспечивает RLS.
Ключи `service_role` / `secret` в этот файл вписывать нельзя.

## Переменные окружения Netlify (только секреты функции Telegram)
Добавляются владельцем вручную в настройки КОНКРЕТНОГО сайта в Netlify (не Shared variables).
- `SUPABASE_URL` — адрес проекта Supabase (функция читает заказ из базы)
- `SUPABASE_SERVICE_ROLE_KEY` — секретный ключ Supabase (нужен только функции, в браузер не попадает)
- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather
- `TELEGRAM_CHAT_ID` — номер личного чата владельца с ботом

Пока хотя бы одна переменная не задана, уведомления не отправляются.
После изменения переменных нужна повторная публикация сайта.

## Как посмотреть локально
Откройте `index.html` в браузере.

## Что заменит владелец перед реальным запуском
Название и тексты бренда, настоящие товары и фото, контакты, условия доставки и возврата, политику конфиденциальности, способы оплаты и доставки (в проекте они не подключены), отключение тестовых заказов.
